name: Status tab data
description: Data-source and refresh rules for player, quest, and world-event status.
---

Status navigation has a top-level Status tab with Event Status first and Server Status second; Settings remains separate. Status pages are observational. Reuse the existing validated QuestService state; do not infer quest acceptance from dialogue visibility or weaken catalog matching. Event Status should use plain “Spawned” / “Not spawned” labels for the island rows; keep technical signal details in the copied diagnostic report. Treat `_WorldOrigin.Locations.Tiki Outpost` as a travel-location marker, not proof of eye-event state; Tiki is a permanent island, so an absent eye model means “Not loaded,” not “Not spawned.” The general Sea Events signal does not belong in the visible status page. The Event Status page may use BNN's read-only `InfoLeviathan`, `1` and `CakePrinceSpawner`, `true` queries, rate-limited to 15 seconds while that page is selected. Never call `CakePrinceSpawner` without `true`, because BNN uses that call to open the portal. Derive server age and the four-hour legendary-item cycle estimate from the oldest `_WorldOrigin.Locations.TimeIn` marker, but compare `Workspace:GetServerTimeNow()` and BNN's `tick() - 25200` clock against actual runtime evidence before treating either as authoritative. Held Chalice/Fist ownership does not prove chest origin; it may come from Elite Hunter or another source. State the observed holder and leave acquisition source unknown. For moon timing, preserve BNN/Vxeze phase boundaries but measure `Lighting.ClockTime` progression against real elapsed time; do not call a game-hour difference “minutes.” A matching Elite Hunter model in ReplicatedStorage is only a template signal, not proof the NPC spawned; label it separately from a live model under Workspace.Enemies. Use “I DONT KNOW” for Leviathan spy state -1/nil, and “Leviathan is out” for state 5.

**Why:** The user clarified that Event Status is meant to check event state while the player is away, asked for plain island labels, and confirmed Tiki can simply be unloaded because the island itself does not need to spawn. Runtime reports showed the Tiki travel marker while its local eye model was absent; that marker does not establish eye progress. The user also said a general Sea Events row is unnecessary. Held legendary items can come from Elite Hunter rather than a chest. BNN and Vxeze use the same phase thresholds but label differences in game-clock hours as minutes. Measuring clock speed makes the estimate understandable while keeping source-compatible phase logic. A four-hour timer marks an estimated cycle boundary, not proof that no item can currently be held. Vxeze scans ReplicatedStorage for elites, but a template there can otherwise be mistaken for a live spawn. Their portal-opening call must not be reproduced by status-only code.

**How to apply:** add status fields through StatusFeature and existing status-value rows; keep quest acceptance logic in QuestService, preserve unknown states, rate-limit remote reads, label timing as an estimate, allow calibration to gather samples, and avoid Heartbeat polling.
